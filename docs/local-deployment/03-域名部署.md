# 有域名时，在宝塔部署声间语音房间

以下用 `voice.example.com` 举例，操作时每处都换成自己的实际域名。适用于新的 Ubuntu x86_64 服务器，Docker 和宝塔软件商店安装的宿主机 Nginx 已运行。Docker 提供内部语音应用，宝塔「网站」管理域名、证书和反向代理。

这套部署的应用配置集中在 `/www/voice-room/compose.yaml`。域名证书直接在宝塔「网站」中申请和续签。

## 1. 解析域名并放行端口

1. 在域名的 DNS 管理后台添加 **A 记录**。例如域名是 `example.com`，要使用 `voice.example.com`，主机记录填 `voice`，记录值填新服务器公网 IPv4。
2. 在云安全组和宝塔防火墙同时放行入站 TCP **80、443**。本教程采用宝塔文件验证申请证书，公网 80 应能直达这台主机。若域名已有 AAAA 记录，确认它也能到达同一网站。
3. 在宝塔终端执行下面的命令。第一条应显示 `x86_64`，第二条应输出 Compose 版本，第三条应能查到你的公网 IPv4。

```bash
uname -m
docker compose version
getent ahostsv4 voice.example.com
```

## 2. 在 compose.yaml 填写凭据并启动 Docker

以 `root` 在宝塔终端执行：

```bash
install -d -m 700 /www/voice-room
touch /www/voice-room/compose.yaml
chmod 600 /www/voice-room/compose.yaml
```

在「宝塔 → 文件」中编辑 `/www/voice-room/compose.yaml`，粘贴**完整编排模板**。在 `environment` 下，把 `ZEGO_APP_ID` 和 `ZEGO_SERVER_SECRET` 的占位文字换成同一项目的数字 AppID 和 32 位 ServerSecret，保留英文双引号和缩进。保存填好凭据的服务器文件。[完整编排模板](../../voice-room/deploy/compose.bt.yaml) · [ZEGO 项目信息](https://doc-zh.zego.im/console/project-info)

进入「Docker → 容器编排 → 添加容器编排 → 从文件创建」，选择刚填好的 `/www/voice-room/compose.yaml`，名称设为 `voice-room` 并部署。只有手动输入入口时，粘贴填好凭据的完整 YAML。单独的环境变量框留空。等下面的健康检查返回 `{"configured":true}` 后再继续。[宝塔编排操作步骤](02-Docker编排模板.md)

```bash
curl -fsS http://127.0.0.1:3080/api/health
```

## 3. 在宝塔创建域名站点

打开 **网站 → 添加站点**。若界面按项目类型分类，可从「PHP 项目」进入并选择「纯静态」。按下表填写后提交。[宝塔添加站点说明](https://docs.bt.cn/user-guide/site/php/create-web/)

| 字段 | 填写内容 |
|---|---|
| 域名 | `voice.example.com`，只填实际域名 |
| 站点目录 | 使用宝塔自动生成的站点目录，例如 `/www/wwwroot/voice.example.com`，供证书文件验证使用。`/www/voice-room/` 含有密钥，应保持在网站公开目录之外。 |
| PHP 版本 | 纯静态 |
| 数据库、FTP | 均选择不创建 |

## 4. 申请域名证书，再添加反向代理

1. 打开 **网站 → 该域名的设置 → SSL → Let's Encrypt**。选中该域名，选择文件验证，申请并部署证书。先确认 `https://voice.example.com/` 的证书受信任；此时看到宝塔的默认站点页是正常的。[宝塔 SSL 配置说明](https://docs.bt.cn/user-guide/site/php/site-config/ssl/)
2. 进入该站点的 **反向代理 → 添加反向代理**，按下表填写并保存。[宝塔反向代理配置说明](https://docs.bt.cn/user-guide/site/php/site-config/reverse-proxy)
3. 打开 `https://voice.example.com/api/health`，确认看到 `{"configured":true}`。然后回到站点的 SSL 页面开启「强制 HTTPS」。确认面板里该证书的自动续签状态，保留文件验证使用的 `/.well-known/acme-challenge/` 路径。

| 反向代理字段 | 填写内容 |
|---|---|
| 代理名称 | `voice-room` |
| 代理目录 | `/`（部分版本在「高级功能」中显示） |
| 目标 URL | `http://127.0.0.1:3080` |
| 发送域名 | 实际访问域名，例如 `voice.example.com` |
| 缓存 | 关闭，让房间列表及时更新 |
| 内容替换 | 留空 |

## 5. 从公网验证通话

用电脑访问 `https://voice.example.com/`，建房并允许麦克风。手机用移动网络打开邀请链接，或者输入六位房号加入。分别讲话，确认双方可以互听；测试完在大厅关闭测试房。

| 现象 | 如何定位 |
|---|---|
| 宝塔申请证书失败 | 从外部网络核对域名解析、80 端口和文件验证路径。如果有代理或 CDN，确认验证请求能送达新服务器。 |
| 本机健康检查正常，域名却显示 502 或默认站点 | 核对 DNS 指向的 IP，检查此域名对应的站点是否启用了代理，代理目录应为 `/`，目标应为 `http://127.0.0.1:3080`。 |
| `configured` 为 `false` | 核对导入的 `compose.yaml` 中两个凭据是否已填好，在原编排中重新部署并重建容器，再查健康接口。 |
| 页面能打开但无法说话 | 用系统浏览器打开证书有效的 HTTPS 域名，检查麦克风权限。若进房失败，核对 AppID 与 ServerSecret 是否属于同一项目，并确认项目语音服务可用。 |
