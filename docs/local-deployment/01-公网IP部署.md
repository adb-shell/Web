# 只有公网 IPv4 时，在宝塔部署声间语音房间

适用于一台新的 Ubuntu x86_64 服务器，已有固定公网 IPv4，Docker 和 Nginx 均已安装，Nginx 来自宝塔软件商店。完成后，访客打开 `https://你的公网IP/`，允许麦克风即可通话。以下终端命令均以 `root` 运行。

在宝塔「文件」中，日常只需打开这一个目录：

```text
/www/voice-room/
├── compose.yaml    # Docker 编排，包含本机的 AppID 和 ServerSecret
└── ip-https.sh     # 第 4 步下载的公网 IP 证书部署脚本
```

## 1. 检查环境和端口

在宝塔「终端」执行：

```bash
uname -m
docker compose version
/www/server/nginx/sbin/nginx -t
ss -ltn 'sport = :443'
```

- 架构应为 `x86_64`，Compose 应显示版本号，Nginx 语法检查应通过。教程使用 `tunneluser/voice-room:0.3.1` 的 Linux amd64 镜像。
- 在云服务器的**安全组**和**宝塔 → 安全 → 防火墙**放行入站 TCP **80 和 443**。80 用于验证 IP 和续期，443 供访客访问。应用的 3080 只监听本机。
- 如果最后一条命令列出了监听 443 的服务，本次新站可选空闲的 **8443**，在两处防火墙同时放行 80 和 8443，第 4 步也使用 8443。
- 新服务器上请让第 4 步的脚本创建 IP 站点。若已在面板中绑定了同一 IP，脚本会因配置冲突停止，单改端口也无法绕过该冲突。此时应复用已有站点及其有效 IP 证书，将根路径反代至 `http://127.0.0.1:3080`。

## 2. 在 compose.yaml 填写 AppID 和 ServerSecret

先用 root 在宝塔终端创建项目目录和编排文件。

```bash
install -d -m 700 /www/voice-room
touch /www/voice-room/compose.yaml
chmod 600 /www/voice-room/compose.yaml
```

打开「宝塔 → 文件」，编辑 `/www/voice-room/compose.yaml`，先粘贴**完整编排模板**。找到 `environment` 下的两行，将 `ZEGO_APP_ID` 的占位符替换为数字 AppID，将 `ZEGO_SERVER_SECRET` 的占位符替换为同一项目的 32 位 ServerSecret。保留英文双引号和缩进，保存文件。填写过密钥的编排仅保存在服务器私有目录。[完整编排模板](../../voice-room/deploy/compose.bt.yaml) · [ZEGO 项目信息](https://doc-zh.zego.im/console/project-info)

## 3. 在宝塔启动容器

打开「Docker → 容器编排 → 添加容器编排 → 从文件创建」，选择第 2 步填好的 `/www/voice-room/compose.yaml`，名称填 `voice-room`，点击「部署」。如果只有手动输入入口，粘贴填好凭据的完整 YAML。面板单独的环境变量框留空。[宝塔编排操作步骤](02-Docker编排模板.md)

在宝塔终端检查后端：

```bash
docker ps --filter name=voice-room
curl -fsS http://127.0.0.1:3080/api/health
```

预期返回 `{"configured":true}`。看到 `false` 时，核对所导入编排的两个字段，在原编排中重新部署并重建容器，再查一次。本机检查通过后再申请证书。

## 4. 为公网 IP 配置 HTTPS

在新服务器宝塔终端，将下面第一行改为**新服务器的实际公网 IPv4**。如果第 1 步选择了 8443，将第二行也改为 `VOICE_PORT=8443`。

```bash
VOICE_IP='替换为你的公网IPv4'
VOICE_PORT=443
curl -fL --retry 3 https://raw.githubusercontent.com/adb-shell/Web/v0.3.1/voice-room/deploy/ip-https.sh \
  -o /www/voice-room/ip-https.sh &&
  bash /www/voice-room/ip-https.sh "$VOICE_IP" "$VOICE_PORT"
```

脚本使用 80 端口完成 HTTP 验证，申请受浏览器信任的短期 IP 证书，并为宝塔 Nginx 写入 HTTP 和 HTTPS 配置。它会把 HTTPS 流量转发到 `127.0.0.1:3080`，并设置每天检查两次的续期任务。让公网 80 持续可达，以便后续自动验证。[项目脚本](https://github.com/adb-shell/Web/blob/v0.3.1/voice-room/deploy/ip-https.sh) · [Let’s Encrypt 的 IP 证书说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)

成功时终端会打印「测试地址」。443 对应 `https://你的公网IP/`，8443 对应 `https://你的公网IP:8443/`。脚本自动将证书和续期文件写入 `/var/lib/zego-voice/`，将站点配置写入宝塔 Nginx 的配置目录。日常查看容器可进入宝塔「Docker」；脚本创建的站点可能不会单独列在「网站」中。

## 5. 上线验收与排错

1. 用手机流量打开终端打印的 HTTPS 地址，并在地址末尾访问 `/api/health`，应显示 `{"configured":true}`，浏览器应信任证书。
2. 电脑打开首页建房并允许麦克风；手机用邀请链接或房号加入。两端应看到「用户01」「用户02」，分别讲话确认互相听得见。健康接口只验证配置格式，实际通话才能验证这组项目凭据可用。
3. 在终端运行 `systemctl list-timers zego-voice-renew.timer`，确认能看到下一次续期检查时间。

| 现象 | 处理方法 |
|---|---|
| 证书验证失败 | 核对公网 IPv4、云安全组、宝塔防火墙和 NAT 转发，确认外部 TCP 80 能到这台服务器。修好后用同一 IP、端口重新运行第 4 步。 |
| HTTPS 返回 502 | 先查 `curl -fsS http://127.0.0.1:3080/api/health`。本机请求也失败时运行 `docker logs --tail 50 voice-room`；本机正常时查看 Nginx 的代理配置。 |
| 无法启用麦克风 | 用系统浏览器打开证书有效的 HTTPS 地址，在该站点的浏览器权限中允许麦克风，再重新进房。 |
| 要查看续期结果 | 运行 `journalctl -u zego-voice-renew.service -n 30 --no-pager`。 |
